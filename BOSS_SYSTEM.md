# Система боссов

## 1. Общая архитектура
Босс — **сюжетное многофазное событие**, а не одна сложная расстановка. Ключевое решение (снимает риск для 100 уровней и решателя): босс = **последовательность обычных, по отдельности решаемых под-уровней** (фаз). Никаких изменений `src/core` или solver. Данные боссов — `src/game/boss.ts`; оркестрация — методы `App` в `src/ui/app.ts` (generic, без ветвлений `id===N`).

## 2. Поток запуска
```
startLevel(id)
  → bossFor(id)            // есть данные босса на этом слоте?
  → startBoss(def)         // интро-сцена деда
  → playBossPhase(def,run) // текущая фаза = runLevel(subLevel, boss-контекст)
  → (игрок проходит под-уровень) onExitDone → completeLevel()
  → onBossPhaseDone(def,run,endState)
       ├─ не последняя фаза → boss-transition overlay → boss-continue → playBossPhase(nextRun)
       └─ последняя фаза   → recordResult + markBossDone
                             → (слот 100) completeCampaignFinale() → финальная сцена лиги
                             → иначе showBossVictory()
```
Обычные уровни через boss-логику не проходят: `bossFor(id)` возвращает `undefined` → `runLevel(level)`.

## 3. `BossRun`
`{ bossId: number; phaseIndex: number; done: boolean }` — сериализуемо. Чистые функции в `boss.ts`: `createBossRun`, `currentPhase`, `advancePhase`, `restartBoss`, `reviveBossRun`, `bossProgress`. UI хранит текущий `run` в замыкании `runLevel` (передаётся через `boss` param).

## 4. Переходы фаз
Между фазами — короткий overlay `boss-transition` (data-testid): «Фаза N из M пройдена» + сюжетная реплика деда (`yardDirector.react('boss-phase')`) + кнопка `boss-continue`. Переход НЕ зависит от таймеров анимации. Защита от double-completion: `completeLevel()` — `if (finished) return; finished = true;` (одна фаза не может завершиться дважды; повторный клик/onExitDone игнорируется).

## 5. Restart
Кнопка «Заново» перезапускает **текущую фазу** (обычный `createState` под-уровня): ранние пройденные фазы не теряются, `run.phaseIndex` не меняется. Полный сброс босса — выход в меню и повторный вход.

## 6. Undo
Undo работает **только внутри текущей фазы**. Каждая фаза — свежий вызов `runLevel` с новым `undoStack`, поэтому отмена не пересекает границу фаз (e2e: на свежей фазе `btn-undo` disabled). Отменить сам переход между фазами нельзя.

## 7. Save / revive
`SaveData.bossDone: number[]` — слоты пройденных боссов (union при merge, идемпотентно). Пишется `markBossDone(id)` только после последней фазы. Прогресс кампании (`stars[id]` через `recordResult`) — тоже только после полной победы, поэтому обрыв на промежуточной фазе не засчитывает уровень. `reviveBossRun(raw, def)` санитизирует: неизвестный `bossId`, `phaseIndex` вне диапазона, мусор → `createBossRun` (с начала), не повреждая общий прогресс. Промежуточный `BossRun` в сейв НЕ персистится (при перезагрузке босс начинается заново — безопасно).

## 8. Связь с `App`
`startBoss`, `playBossPhase`, `onBossPhaseDone`, `showBossVictory`, `completeCampaignFinale`, `levelById`. `runLevel` принимает опциональный `boss?: { def, run }`, ведущий `completeLevel()` в `onBossPhaseDone` вместо `finishLevel`.

## 9. Связь с `BoardView`
Никакой boss-специфики в `BoardView`: фаза — обычный уровень, `BoardView` рисует его как есть. Реакции двора (пыль/куры/ворота) работают штатно; сюжетные реплики деда навешивает `App`/`YardDirector`.

## 10. Связь с solver
Каждая фаза — реальный уровень кампании (`sourceLevelId`), поэтому её проходимость доказывается штатным `solve()`. Тест `tests/boss.test.ts` прогоняет solver по всем фазам всех боссов (solvable, optimal>0, звёздный маршрут если фаза требует звезду).

## 11. Boss HUD
В шапке уровня-фазы: `⚡ {название босса}` + чип `Фаза N из M` (`data-testid=boss-phase`). Помещается на 320×568 и landscape 667×375 (проверено e2e «критический UI не обрезается»). Локализован ru/en/tr. Без мелкого текста, не перекрывает поле.

## 12. Интро и победные сцены
- Интро: `boss-intro` overlay — иконка ⚡, название, завязка, кнопка «Взяться за дело» (`boss-start`).
- Победа: `boss-victory` overlay — 🏆, звёзды, уникальный текст `victoryKey`, кнопки «Дальше»/«Меню». Конфетти. Для слота 100 при первом прохождении вместо этого — финальная сцена Высшей лиги (`campaign-ending`).

## 14. Как добавить шестого босса
1. Добавить запись в `BOSSES` (`src/game/boss.ts`): `id` (слот кампании), `nameKey/introKey/victoryKey`, `phases[]` (каждая — `sourceLevelId` существующего проходимого уровня + опц. `objective.requireStar`, `grandpaLineKey`).
2. Добавить ключи локализации `boss.*` в ru/en/tr (`src/game/i18n.ts`).
3. Ничего в `app.ts` менять не нужно — оркестрация generic.
4. Добавить кейс в `tests/boss.test.ts` (структура) — проходимость проверится автоматически циклом по `BOSSES`.
5. Добавить слот в параметризованный e2e-блок «Боссы …».

## 15. Обязательные тесты
- Unit (`tests/boss.test.ts`): структура (≥5 боссов, слоты, ≥2 фазы), `bossFor`, существование под-уровней, **проходимость каждой фазы solver**, контроллер (advance до done, restart, `bossProgress`, сериализация/revive/санитизация мусора).
- e2e (`e2e/game.spec.ts`): полный проход каждого босса (интро→фазы→победа), прогресс только после победы, restart фазы, undo не через границу, TV, босс 100 → открытие лиги один раз, повтор без повторных наград, отсутствие ошибок консоли.

## 16. Известные ограничения
- Промежуточное состояние босса не сохраняется между сессиями (перезагрузка → босс с начала). Осознанно: проще и безопаснее, чем персистить `phaseIndex`.
- `worldChange` в данных фаз (`boss-dust`/`boss-smoke`/`boss-wind`/…) описаны, но как декоративные CSS-классы применяются минимально — расширяемо.
- Звук фаз — синтез WebAudio (см. `AUDIO_ASSETS_REQUIRED.md`), не финальные сэмплы.
- e2e-завершение фазы использует хук `__e2eWinLevel` (только `MODE==='e2e'`), т.к. под-уровни не решаются тривиальным drag; реальная проходимость покрыта solver-тестом.
