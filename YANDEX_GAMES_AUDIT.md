## 3. Блокирующие нарушения

P0-нарушений не найдено. Ниже сохранены первичные доказательства шести P1; все шесть исправлены и закрыты регрессионными тестами до формирования релиза:

### P1-01 — звук не останавливается на пользовательской паузе

Статус после исправления: **PASS** — общий mute state учитывает пользовательскую паузу; E2E проверяет master gain `0.5 → 0 → 0.5`.

- Требование: качество паузы и рекомендуемый пункт 6.3; заявленный аудит также требует остановить музыку при пользовательской паузе.
- Доказательство: `showPause()` вызывает только `setGameplay(false)` и `engineStop()`, но не включает `audio.duck()` и не останавливает музыку (`src/ui/app.ts:946-949`). `syncAudioPause()` учитывает только platform/ad (`src/ui/app.ts:296-298`).
- Сценарий: запустить уровень со включённой музыкой → нажать «Пауза» → фоновая музыка продолжает планироваться и master gain остаётся активным.
- Риск: незавершённая пауза, жалобы QA/пользователей; средний риск замечания.
- Исправление: добавить отдельное состояние пользовательской паузы в общий расчёт audio duck и тест.

### P1-02 — облачные записи могут завершиться не по порядку

Статус после исправления: **PASS** — `SaveStore` отправляет immutable JSON-снимки через последовательную promise-очередь; unit-тест проверяет порядок.

- Требование: пункт 1.9, сохранение сразу после действия без потери нового прогресса.
- Доказательство: каждый `persist()` независимо запускает `platform.saveData(this.data)` без очереди и без снимка (`src/game/save.ts:180-182`), а cloud использует асинхронный `player.setData(..., true)` (`src/platform/yandex.ts:284-291`).
- Сценарий: быстро изменить язык, звук и результат уровня; серверный ответ первой записи может прийти после последней.
- Риск: устаревший cloud-сейв на другом устройстве.
- Исправление: сериализовать сохранения и передавать JSON-снимок состояния.

### P1-03 — быстрый повторный клик может запустить несколько rewarded/interstitial запросов

Статус после исправления: **PASS** — кнопки блокируются до завершения, а адаптер платформы имеет общий single-flight guard и мягко обрабатывает синхронную ошибку SDK.

- Требование: реклама только добровольно и без повторной выдачи/дублирующихся показов.
- Доказательство: `btn-skip`, `btn-hint` и `btn-next` не блокируются перед `await` (`src/ui/app.ts:841-859,867-893,1106-1117`). `bv.interactive = false` блокирует поле, но не DOM-кнопку.
- Сценарий: дважды быстро нажать «Смотреть рекламу — получить подсказку» или «Дальше».
- Риск: два SDK-вызова, преждевременное восстановление ввода, двойной переход.
- Исправление: локальные single-flight guards и disabled до завершения callback.

### P1-04 — меню обрезается на минимальном landscape 568×320

Статус после исправления: **PASS** — добавлен компактный media query; Browser runtime и E2E подтверждают отсутствие overflow и кнопки ≥44 px.

- Требование: пункты 1.6.1.3 и 1.10.1–1.10.3.
- Runtime: Chromium, 568×320, mock, RU, меню. Факт: `menu-play` и `menu-levels` имеют `y=-27`, `menu-rules` заканчивается ниже экрана (`y=303`, `h=44`); системного scroll нет, поэтому элементы недоступны.
- Доказательство CSS: landscape-компоновка включается до 520 px высоты, но фиксированные четыре строки не помещаются (`src/styles.css:1210-1259`).
- Риск: отказ за адаптивность при заявленной ориентации «Любая».
- Исправление: отдельный компактный режим для landscape высотой до 360 px без уменьшения touch-target ниже 44 px.

### P1-05 — старые BoardView не уничтожаются при смене экрана

Статус после исправления: **PASS** — App владеет одним активным `BoardView`, вызывает `destroy()` перед сменой экрана; E2E подтверждает баланс трёх add/remove глобального blur-listener.

- Требование: пункт 1.14, отсутствие зависаний/утечек после длительной сессии.
- Доказательство: BoardView добавляет глобальный `window.blur` и fallback mouse-обработчики (`src/ui/board.ts:129-147`), корректный `destroy()` существует (`src/ui/board.ts:149-169`), но его никто не вызывает (поиск `.destroy(` по `src/` — 0 вызовов).
- Сценарий: последовательно открыть/перезапустить десятки уровней; старые экземпляры остаются достижимыми из обработчиков window.
- Риск: рост памяти и лишние callbacks в длинной сессии/старом Safari.
- Исправление: App хранит активный BoardView и уничтожает его перед заменой экрана.

### P1-06 — неверный fallback языка

Статус после исправления: **PASS** — `ru/be/kk/uk/uz → ru`, `tr → tr`, остальные неподдерживаемые языки → `en`; `de` покрыт E2E.

- Требование: пункты 2.10 и 2.14: ru для `ru/be/kk/uk/uz`, английский для остальных неподдерживаемых языков.
- Доказательство: любой код кроме `en` и `tr` переводится в `ru` (`src/game/i18n.ts:566-571`).
- Сценарий: SDK возвращает `de`, `fr`, `es` → интерфейс русский вместо английского.
- Риск: замечание по автоопределению/локализации.
- Исправление: белорусский/казахский/украинский/узбекский → ru, турецкий → tr, остальные → en.

## 5. Результаты SDK-аудита

- **SDK loader — PASS:** динамическая загрузка `/sdk.js` официально допустима; `YaGames.init()` вызывается после `onload`. Абсолютного S3 URL и скачанного `sdk.js` нет.
- **Init — PASS:** один вызов в единственном адаптере. При ошибке через 10 секунд показывается понятное сообщение, бесконечного boot нет (`src/platform/index.ts:9-48`, `src/main.ts:45-49`).
- **Game Ready — PASS:** последовательность по коду и E2E: page start → SDK init → Player/flags → `loadData` → i18n/audio/App → `showMenu` → удалить boot → `ready` → первый `GameplayAPI.start` (`src/main.ts:11-42`).
- **Gameplay API — PASS:** App поддерживает идемпотентное `inGameplay`; start на уровне/resume, stop в меню/победе/паузе/рекламе.
- **Pause/resume — PASS:** системная пауза блокирует pointer events и duck-ит audio; состояние до стартовой рекламы запоминается. Подписки живут весь срок единственного App.
- **Реклама — PASS в коде:** callbacks, логические точки, UI single-flight и общий platform guard покрыты unit/E2E. Реальная выдача рекламы остаётся `MANUAL`.
- **Player data — PASS в коде:** guest/local/cloud/flush и последовательные immutable-снимки реализованы; реальная синхронизация между устройствами остаётся `MANUAL`.
- **Авторизация — N/A:** диалог входа не используется; гостевой режим полноценен.
- **Локализация — PASS:** источник языка — `ysdk.environment.i18n.lang`; fallback соответствует языковым группам, включая `de → en`.
- **Покупки — N/A:** отсутствуют, что обязательно для TV.
